The panel is htmx-loaded on first open rather than rendered into every admin page, matching the distributor bell (Task 21d). Known limit, recorded here so nobody mistakes this for the whole feature: a bell only reaches an admin who is already logged in and looking. The email and SMS alerts (Tasks 61a/61b) are what reach someone who is not. {% endcomment %}
{% comment %} Task 61c. Live bell updates. Found by real-browser testing, not by any test: without this the consumer, the push inside send_admin_notification and broadcast_admin_unread_count were all dead code -- nothing in the page ever opened the socket. The bell only updated on a full reload, and the badge stayed stuck showing the old count after "Mark all read". Mirrors templates/distributors/base_dashboard.html's own client (reconnect with capped backoff, ignore malformed payloads rather than crash the page) instead of inventing a second approach for the same job. The badge is ALSO corrected straight from the htmx swap, not only from the socket: local dev runs on runserver as often as daphne, and runserver has no WebSocket routing at all (CLAUDE.md documents this), so a bell depending solely on the socket would look broken in exactly the environment it is developed in. {% endcomment %}
