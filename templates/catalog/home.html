Paused on hover/focus (WCAG 2.2.2 Pause/Stop/Hide -- auto-updating content must be pausable; pausing on interaction is the simplest correct approach here rather than a separate visible pause control). Every handler is a plain directive-string expression (x-init/@click/@mouseenter/etc.), never a method defined inside the x-data object literal -- the same nested-scope bug already found and fixed once in catalog_banner_form.html applies here too, so this deliberately avoids that shape entirely. CodeRabbit finding (PR #74): hover and focus were tracked as a single implicit "paused" state via clearInterval()/setInterval() pairs alone -- tabbing to the Next button while still hovering, then moving the mouse away, incorrectly restarted the timer because @mouseleave had no idea focus was still active (and vice versa for @focusout while still hovering). Tracked as two explicit booleans instead; the timer only restarts once neither is true. @focusout also checks $el.contains($event.relatedTarget) -- focusout fires when focus moves between the carousel's OWN children too (e.g. prev button -> next button), not just when it leaves the carousel entirely, and only the latter should count as "focus left." {% endcomment %}

Follow-up per direct user feedback ("timeline is supposed to be a circle not a square"): root-caused to this project's own design tokens -- static/src/main.css redefines `--radius-full` to 0.75rem (12px) for pill-shaped buttons, not a true 50% circle, so every square w=h badge using Tailwind's `rounded-full` class (these 4 number circles, plus the arrow-icon and carousel-arrow circles elsewhere on this page) was rendering as a barely-rounded square, not a circle.
